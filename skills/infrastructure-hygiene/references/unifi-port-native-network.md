# Correct a wired client's UniFi native network

Use this when a host has carrier and a DHCP lease, but its wired address and search domain belong to the wrong UniFi network. A successful DHCP activation does not prove the port is assigned to the intended LAN.

1. On the host, compare the current wired lease with prior NetworkManager logs and a known-working Wi-Fi lease. Record the wired interface's MAC from `/sys/class/net/<interface>/address` and keep a working management connection available.
2. If reconnecting Ethernet would replace the working default route, record its original `ipv4.route-metric` and `ipv6.route-metric`, temporarily set both above the working connection's metric, and activate Ethernet. Restore the recorded values after the port works.
3. Authenticate to UniFi OS as described in `unifi-dhcp-dns-via-api-and-ip-diagnostics.md`. Keep credentials, cookies, and CSRF values out of output and tracked files. GET `/proxy/network/api/s/default/stat/sta` and match the host MAC. Read `sw_mac` and `sw_port` from that live wired client record. A disconnected client may be absent; reconnect it before trusting a historical client record.
4. GET `/proxy/network/api/s/default/stat/device` and find the device whose `mac` equals `sw_mac`. Check the matching `port_table` entry and its `port_overrides` entry. GET `/proxy/network/api/s/default/rest/networkconf` and resolve the intended network's `_id` from its name and subnet. Confirm the port and network against the live host lease before writing.
5. Preserve every other override and every other field in the target override. Change only that port's `native_networkconf_id`. PUT `{"port_overrides": <updated-overrides>}` to `/proxy/network/api/s/default/rest/device/<device-id>` with `X-Csrf-Token` from the login response's `X-Updated-Csrf-Token`. Require HTTP 200 and `meta.rc == "ok"`; read `stat/device` again to confirm the stored override.
6. Allow for provisioning, then renew the host's wired connection. An immediate renewal can still return the old lease; poll the live port state and retry after provisioning rather than changing another port based on that first lease. Verify the intended subnet and gateway, the default route after restoring metrics, and HTTPS forced through the wired interface (for example `curl --interface <interface> https://example.com/`).

In the verified case, the first DHCP renewal after UniFi accepted the PUT still returned the previous network. A second renewal returned the intended LAN lease, and forced-interface HTTPS succeeded. That timing alone did not indicate a wrong port selection.
